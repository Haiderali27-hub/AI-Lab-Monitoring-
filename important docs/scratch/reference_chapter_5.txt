SYSTEM DESIGN
In the context of SmartWash Solution, system design marks a critical phase where the
conceptual vision begins to take a structured and implementable form. This stage focuses
on thoughtfully outlining the architecture of the entire system, including its key compo-
nents, modules, and how they interact with one another. It not only defines the technical
blueprint of the platform but also ensures that each part of the system aligns with user
needs, business goals, and functional requirements. By translating abstract requirements
into a tangible, organized framework, this phase serves as the foundation for a scalable,
maintainable, and efficient solution. Ultimately, system design bridges the gap between
planning and development, guiding the project from idea to reality.
5.1 Structure Diagrams
A structure diagram acts as a blueprint that reveals how different components within
a system are organized and connected. It provides a visual layout of the system’s archi-
tecture, making it easier to understand how each part contributes to the overall function-
ality. Whether it’s a database, application, or a complete software solution, the structure
diagram illustrates the hierarchy, arrangement, and interactions among the modules, en-
suring that they work together seamlessly much like a well-fitted puzzle[45].
In the context of SmartWash Solution, structure diagrams serve as essential tools for
visualizing the architecture of the platform. They offer a high-level overview of how ma-
jor system components such as user modules, services, databases, and controllers interact
to deliver core functionalities. These diagrams are instrumental in identifying relation-
ships and dependencies between components, streamlining system design, and ensuring
coherent development. By offering a clear and comprehensive depiction of the system’s
backbone, structure diagrams support effective communication among developers, design-
ers, and stakeholders, and guide the implementation of a stable, well-integrated solution.
5.1.1 Class Diagram
A class diagram is a visual representation that outlines the structure of a system and
the relationships between its essential components. It uses standardized symbols to de-
pict classes such as users, services, or payments along with their attributes (what they
have) and methods (what they can do). These diagrams help simplify complex systems by
breaking them into understandable, organized components, providing a clear overview of
the system’s architecture. Each class serves as a blueprint for creating real-world objects
in the software, ensuring consistency and reusability across the system. Relationships be-
tween classes, including inheritance, associations, aggregations, and dependencies, are ex-
plicitly defined, allowing developers and stakeholders to understand how different parts of
the system interact. Class diagrams also support better planning, design, and documenta-
tion, helping teams anticipate potential design issues, enforce object-oriented principles,
and maintain system integrity throughout development. By offering a comprehensive

5.1.2 Deployment Diagrams

tem, showing how its software components are distributed across hardware devices during
runtime. Essentially, it maps out where each part of the system lives, whether it’s a spe-
cific server, computer, or other device, and illustrates the interactions between these
elements. It’s a valuable tool for understanding how the physical infrastructure supports
the system’s functionality, highlighting the relationship between hardware and the soft-
ware running on it. This diagram provides insight into the deployment of software on
various nodes, which helps with scalability, performance, and system maintenance[47].

5.2 Behavioral Diagrams
Behavioral diagrams serve as dynamic blueprints that illustrate how a system operates
during its execution. These diagrams capture the interactions between various compo-
nents, users, and external systems, showing how data flows and processes are carried
out. They are essential for understanding the real-time functionality of software and its
underlying processes. For example, an activity diagram provides a detailed sequence of
actions within a system, such as the steps involved in a business process[48].
Behavioral diagrams are particularly valuable for visualizing the dynamic behaviors
of a system. By highlighting how data moves and how different system parts interact over
time, these diagrams offer stakeholders an insightful view into the system’s operational
flow. They help identify potential bottlenecks, improve system performance, and ensure
that the system functions as intended.
5.2.1 Activity Diagrams
An activity diagram in UML is a specialized type of diagram that goes beyond the
simplicity of a traditional flowchart. It’s designed to show the dynamic flow of activities
or tasks within a system. While similar to a flowchart, an activity diagram provides

5.2.2 Communication Diagrams
UML Communication Diagrams provide a structured way to visualize how objects
interact within a system by focusing on the exchange of messages between them. These
diagrams are similar to sequence diagrams but emphasize the relationships and message
flow among objects rather than the time sequence. Each object is represented along
with its links to others, and numbered arrows are used to indicate the order and direc-
tion of message passing.Unlike object diagrams, which simply show static relationships,
communication diagrams highlight dynamic behavior by showing how processes are trig-
gered through communication. They are particularly useful for identifying how multiple
components collaborate to fulfill a specific use case. This perspective helps developers
and analysts ensure that object responsibilities and interactions are clearly defined and
logically organized[50].

interact with each other to complete a customer’s service booking. The diagram shows
the sequence of actions from the customer accessing the system to the confirmation of

5.2.3 Sequence Diagrams
UML Sequence Diagrams are used to visualize the flow of events within a system,
showing how components or objects interact over time. They provide a timeline-based
view, with the vertical axis representing time and the horizontal axis representing inter-
acting objects. Each object has a lifeline, and interactions are shown as arrows indicating
messages or method calls in sequence. These diagrams help track workflows, message ex-
changes, and system behavior, making them invaluable for designers, developers, and
stakeholders when analyzing or building complex systems[51].
The sequence diagrams for SmartWash Solution depict the chronological interactions
between system components during the service booking process. They show the flow of
messages exchanged over time, illustrating the order of tasks such as user authentication,
slot selection, payment processing, and service provider notifications.
