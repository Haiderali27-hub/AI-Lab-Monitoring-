\section{System User Interfaces}
SmartExam has two front ends \cite{user_interface_guide}: a WPF desktop client (.NET~9) in which students sit the exam, and a React web panel with one route group per role (\texttt{/admin}, \texttt{/teacher}, \texttt{/invigilator}, \texttt{/student}). All figures use the seeded demo data. The web figures are captured from the running panel by a Playwright script (\texttt{Admin\_Web\_Panel/tests/docs}) against the in-memory backend. The desktop figures are rendered off-screen from the client's own XAML views, because the lockdown window cannot be captured safely on a development PC.

\subsection{Student Desktop Client}
The student signs in with email or roll number (Figure~\ref{fig:ui_student_login}). The client reads the BIOS, system-disk and baseboard serials; the server hashes them with SHA-256 and keeps only the hash in \texttt{DeviceBindings}, so a login from another PC is refused (FR1). The exam dashboard (Figure~\ref{fig:ui_student_diagnostics}) shows only exams the student is eligible for, with instructions, permitted applications, lab, seat and remaining time (FR3). It runs the readiness checks (FR2): network, clock skew, screen capture, webcam, microphone, secure mode (monitors, remote session, virtual machine, keyboard hook) and disk space. Here secure mode fails because a second monitor is attached, so \emph{Start Exam} stays disabled; an exam with \texttt{RequireReadiness} needs a passing check less than 30 minutes old.

The exam window (Figure~\ref{fig:ui_student_workspace}) opens maximized, borderless and topmost (FR4). A low-level keyboard hook blocks the Windows and menu keys, PrintScreen, Alt+Tab, Alt+F4, Alt+Esc, Ctrl+Esc and Ctrl+Shift+Esc, while guard services watch processes, the clipboard and USB drives. The student picks a question from the list on the left and types the answer; coding answers go into a monospace text box. Every edit is kept in an AES-GCM encrypted backup on disk and sent to the server within 10~s; saves made offline are queued and replayed (FR6). The footer shows the last save time.

\subsection{Exam Setup}
The teacher dashboard (Figure~\ref{fig:ui_teacher_dashboard}) counts the teacher's exams, the running ones and the ended exams waiting for grade review. It lists scheduled exams with \emph{Manage}, \emph{Edit} and \emph{Delete}, and links each ended exam to \emph{Review Grades}.

A four-step wizard creates an exam: basic information, questions (MCQ, coding with test cases, theory), rules, and students (FR8). Step~3 (Figure~\ref{fig:ui_create_exam_rules}) holds the integrity rules: allowed applications, lockdown mode (Off, Report, Enforce), multi-monitor flag, required readiness, webcam and microphone, practice exam, early join, minimum attendance, capture intervals, seat enforcement, AI evaluation and the plagiarism threshold.

\subsection{Live Proctoring}
The desktop client posts heartbeats, events and screen captures to \url{/api/monitoring}, and the server pushes updates to the live monitor (Figure~\ref{fig:ui_teacher_live_monitoring}) over the SignalR hub \url{/hubs/monitoring} (FR5, FR10). Through \texttt{ExamProctors}, invigilators see only the exams assigned to them. Each tile shows the student's seat and PC, readiness, latest capture, latest alert, progress and a status (Stable, Warning, Suspicious, Critical, Submitted); the header shows the remaining time with \emph{Extend Time} and \emph{Force End Exam}. The thumbnails here were uploaded by a scripted test client.

\subsection{Evaluation}
The results page lists each submission with its score and SHA-256 receipt. Opening one (Figure~\ref{fig:ui_teacher_ai_grading}) shows every answer next to its AI evaluation: suggested mark, confidence, engine, justification, test-case results (hidden cases marked) and code-analysis signals. C++ answers are compiled and run against weighted test cases in a Docker \texttt{gcc:13} container (FR11.1); theory answers get a TF-IDF similarity score (FR11.2). The teacher accepts the mark or saves an override, stored in \texttt{TeacherGradeOverrides}.

The \emph{Plagiarism Flags} tab (Figure~\ref{fig:ui_plagiarism}) shows a pairwise heat map built by k-gram winnowing, which ignores identifiers and comments in code (FR11.3). A pair at or above the exam's threshold gets a card with both answers side by side and the matched lines highlighted; the teacher records the decision as a grade override.

Enums are stored as their names, and defaults are set by the application. Table~\ref{tab:physical_tables} lists all 29 tables; evidence (\texttt{Screenshots}) came with M5, \texttt{Incidents} and \texttt{ExamProctors} with M10, and \texttt{TestCaseResults} with M11. \subsection{AiGradingResults}

A teacher override in \texttt{TeacherGradeOverrides} takes precedence over \texttt{SuggestedMarks}.
