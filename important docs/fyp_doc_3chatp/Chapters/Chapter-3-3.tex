Initially, the project is divided into five core areas: Requirements, Design, Implementation, Testing, Documentation. The implementation phase is then further divided into the twelve module clusters as defined in the product scope. The complete hierarchy is shown in Figure~\ref{fig:wbs}.

\subsection{Critical Path Method}

The Critical Path Method (CPM) identifies the sequence of activities that determine the shortest project duration \cite{spp1}. If any task on this critical path is delayed, the whole project will be delayed. Non-critical path activities are slack activities, which are buffers that allow schedule slippage without affecting the project completion date. This project is modeled as a CPM network beginning with Activity A (Gathering Requirements, 1 week) which has three dependent paths. Path 1 includes Task B (Lockdown Client Development, 3 weeks) followed by Task E (AI Monitoring, 3 weeks). Path 2 includes Task C (Admin Dashboard, 2 weeks) and Task D (Question Bank, 2 weeks) that both feed into Task G (Unit Testing, 1 week). Path 3: Task F (Student Exam Client, 2 weeks). Tasks E, G and F all feed into Task H (System Integration Testing, 1 week) and conclude with Task I (System Deployment, 1 week) as depicted in Figure~\ref{fig:criticalpath}.

The critical path is A $\rightarrow$ B $\rightarrow$ E $\rightarrow$ H $\rightarrow$ I with total length of 9 weeks (1+3+3+1+1). There is no slack on these critical tasks, so any delay will directly delay the deployment date. Path 2 tasks (C, D, G) have 1 week slack and Path 3 (Task F) has 4 weeks slack making them resource-sourcing pools if critical tasks fall behind.

\subsubsection{Schedule Control and Review}

SmartExam uses sprint burn-down charts \cite{scrum1} instead of passive calendar checks. Progress is measured at the end of each sprint against initial plans. If the percentage of completed story points drops below 80\% then there is a recovery session up to one day before the next sprint starts to identify delays early and not only see them during the last integration sprint.
