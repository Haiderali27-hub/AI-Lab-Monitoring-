\subsection{Critical Path Method}

The critical path method identifies the longest sequence of dependent activities that determines the minimum project duration \cite{spp1}. Any delay in a critical path activity directly delays the entire project completion date, whereas activities not on the critical path have some flexibility known as slack or float. In this FYP, the critical path method was applied to nine key project activities to determine which tasks require the strictest schedule adherence.

The project begins with Activity A (Gather Requirements, 1 week), after which the work splits into three parallel development tracks. The first track covers Activity B (Lockdown Browser Integration, 3 weeks) followed by Activity E (AI Monitoring Module Development, 3 weeks). The second track covers Activity C (Admin Dashboard Development, 2 weeks) followed by Activity D (Question Bank Module Development, 2 weeks) and then Activity G (Unit Testing, 1 week). The third track covers Activity F (Student Exam Interface Development, 2 weeks). All three tracks converge at Activity H (Integration Testing, 1 week), which is followed by Activity I (System Deployment, 1 week). The critical path network is illustrated in Figure~\ref{fig:criticalpath}.

\begin{figure}[H]
\centering
\includegraphics[width=0.95\linewidth]{Figures/critical_path.png}
\caption{Critical Path of the Proposed Project Activities}
\label{fig:criticalpath}
\end{figure}

The critical path of the project follows the sequence Start, A, B, E, H, I, End, with a total duration of 9 weeks (1 + 3 + 3 + 1 + 1). This is the longest path through the network and therefore determines the minimum time required to complete the project. Activities on this path have zero float, meaning any delay in requirements gathering, lockdown browser integration, AI monitoring module development, integration testing, or system deployment will directly push back the project deadline. The second track (A, C, D, G, H, I) has a total duration of 8 weeks and therefore carries 1 week of positive slack. The third track (A, F, H, I) has a total duration of 5 weeks and carries 4 weeks of slack, making it the most flexible path in the schedule.

\subsubsection{Schedule Control and Review}

Schedule control in this project depends on regular sprint review, comparison of completed tasks against planned outcomes, and early adjustment when a task begins to slip \cite{scrum1}. This approach is more useful than passive calendar tracking because it links time management with actual deliverables such as working modules, diagrams, documentation updates, and testing evidence.
