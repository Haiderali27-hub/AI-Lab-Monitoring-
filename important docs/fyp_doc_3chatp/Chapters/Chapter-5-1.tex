\chapter{SYSTEM DESIGN}
\label{chap:system_design}

In this chapter, we detail the technical architecture of SmartExam. We translate our conceptual requirements into concrete component structures, database designs, and runtime diagrams. This acts as our development blueprint, ensuring that our WPF client, API controllers, WebSocket hubs, and grading services coordinate smoothly under load.

\section{Structure Diagrams}
Structure diagrams map out the static layout of our system, showing how the database models, server applications, and client executables connect \cite{structure_diagram_techopedia}. They define the compile-time boundaries, helping our team build individual components in parallel without integration surprises.

In the design of the SmartExam system, structure diagrams serve as essential tools for visualizing the static backbone of the application. They offer a high-level overview of how major database entities, service layers, controllers, client terminals, and remote database servers interact to deliver core functionalities like authentication, lockdown boundaries, and grading pipelines. By defining relationships and dependencies between compile-time components, structure diagrams streamline system design and ensure cohesive, concurrent development.

As shown in Figure~\ref{fig:deployment_diagram}, we divide our platform into three physical tiers. The Client tier contains the WPF student client running locally. The Web tier serves the React admin panel to teachers. Communication uses HTTPS for REST endpoints and WebSockets for real-time telemetry.
