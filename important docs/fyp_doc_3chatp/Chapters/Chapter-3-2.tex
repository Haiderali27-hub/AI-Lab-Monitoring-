\section{Deliverables of the Project}

Deliverables are the tangible, measurable outputs created and delivered during the project lifecycle \cite{del1}. In our Final Year Project (FYP), these are structured into five main categories:

\subsection{Requirements and Analysis Deliverables}
Deliverables in this phase include the problem statement, Statement of Scope (SOP), literature review, and stakeholder interview results. Additionally, functional and non-functional requirements are documented. These materials establish the baseline for subsequent design and development stages by defining the system's goals and boundaries \cite{srs1}.

\subsection{Design Deliverables}
During the design phase, we document system architecture, technology stacks, module breakdowns, and process flows. These are visualized through Data Flow Diagrams (DFDs), Entity-Relationship Diagrams (ERDs), use case diagrams, and scheduling artifacts like Gantt charts \cite{biometric1}. These designs decompose the system into distinct modules to guide development tasks and responsibilities.

\subsection{Prototype and Module Deliverables}
We will deliver a working prototype consisting of twelve integrated modules:
\begin{enumerate}
    \item \textbf{Student WPF Client:} Enforces hardware ID (HWID) binding, full-screen lockdown, system process monitoring (telemetry), and auto-saving.
    \item \textbf{Teacher/Admin Web App:} Built with React, providing exam scheduling, live student monitoring, and post-exam reporting.
    \item \textbf{REST API Backend:} Built with ASP.NET Core and Neon PostgreSQL, handling authentication, scheduling, submission processing, and audit logging.
\end{enumerate}
For any module to be counted as completed, it must pass end-to-end tests validating both front-end UI and back-end endpoints \cite{srs1}. A UI interface lacking a functional backend endpoint is not considered delivered.

\subsection{Testing and Validation Deliverables}
Testing deliverables focus on verifying system correctness. These include unit test reports for individual modules, integration test reports to verify inter-module cooperation, and user flow validation notes. These reports confirm the prototype has been rigorously checked and outline the tested scope alongside any remaining constraints.

\subsection{Documentation and Presentation Deliverables}
These academic artifacts disseminate our project findings and include the final FYP report, presentation slides, and responses to supervisor feedback. Documentation is developed incrementally alongside each sprint, ensuring our writing stays within one sprint of the implementation progress.
