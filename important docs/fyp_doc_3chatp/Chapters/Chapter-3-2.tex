\section{Deliverables of the Project}

Deliverables are the tangible, measurable outputs created and delivered during the project lifecycle \cite{del1}. In our Final Year Project (FYP), these are structured into five main categories:

\subsection{Requirements and Analysis Deliverables}
Deliverables in this phase include the problem statement, Statement of Scope (SOP), literature review, and stakeholder interview results. Additionally, functional and non-functional requirements are documented. These materials establish the baseline for subsequent design and development stages by defining the system's goals and boundaries \cite{srs1}.

\subsection{Design Deliverables}
During the design phase, we document system architecture, technology stacks, module breakdowns, and process flows. These are visualized through Data Flow Diagrams (DFDs), Entity-Relationship Diagrams (ERDs), use case diagrams, and scheduling artifacts like Gantt charts \cite{biometric1}. These designs decompose the system into discrete modules to guide development tasks and responsibilities.

\subsection{Prototype and Module Deliverables}
We will develop a working prototype of twelve integrated modules:
\begin{enumerate}
    \item \textbf{Student WPF Client:} Full screen lockdown, hardware ID (HWID) binding, system process monitoring (telemetry), auto saving.
    \item \textbf{Teacher/Admin Web App:} Developed with React to schedule exams, monitor students in real time, and report after the exam.
    \item \textbf{REST API Backend:} Built on ASP.NET Core and Neon PostgreSQL, responsible for authentication, scheduling, submission processing, and audit logging.
\end{enumerate}
End-to-end tests verify both front-end UI and back-end endpoints in order for a module to be considered finished \cite{srs1}. A functional backend endpoint UI interface is not considered delivered.

\subsection{Testing and Validation Deliverables}
TestingDeliverables are based on verification of correctness of system. These include unit test reports for each module, integration test reports to validate the cooperation between modules, and user flow validation notes. These reports are evidence that the prototype has been tested thoroughly and describe the scope of the testing and any known limitations.

\subsection{Documentation and Presentation Deliverables}
These academic artifacts spread our project findings. It includes the final FYP report, presentation slides and responses to supervisor feedback. Documentation is created incrementally with each sprint, ensuring our writing is one sprint behind the implementation progress.
