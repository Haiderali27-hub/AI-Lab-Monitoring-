\section{Benefits of Proposed System}

SmartExam delivers nine measurable benefits to the institutions and individuals that adopt it.

\textbf{1. Role-based governance.} The system separates what Administrators, Teachers, Invigilators, and Students can see and do. No role can access functions outside its permission boundary. This eliminates accidental or deliberate access violations during exam operations.

\textbf{2. Structured scheduling.} Teachers build exams with defined titles, time limits, allowed application lists, and coding test cases \cite{eassess1}. Sessions are linked to specific laboratories and seat maps before exam day. Nothing is left to informal coordination.

\textbf{3. Hardware-bound access.} Each student's HWID is registered to their account. The exam client refuses to start on an unregistered machine. Students cannot log in from a neighbor's workstation or a personal laptop brought into the lab.

\textbf{4. Controlled exam execution.} The student WPF client runs in fullscreen, disabling Alt+Tab, Task Manager access, and clipboard functions. The environment enforces exam policy technically, not just verbally.

\textbf{5. Live monitoring dashboard.} Invigilators see a real-time grid of all active students. Each card shows focus status, active process names, a recent screenshot thumbnail, and a focus timeline. Alerts surface automatically when thresholds are crossed.

\textbf{6. Structured incident logging.} Every flagged event --- focus switch, blocked application launch, extended inactivity --- is written to the database immediately with a timestamp and session ID. These records persist after the exam ends and form the evidence base for academic review.

\textbf{7. Reliable submission management.} The student client auto-saves work every few minutes. When the timer expires or a teacher forces a close, the final snapshot is uploaded to the server and locked. Students cannot modify submissions retroactively.

\textbf{8. AI-assisted evaluation.} Coding submissions run against pre-configured test cases in an isolated execution environment. Theory questions are graded using semantic similarity comparison. This reduces manual marking time for large student cohorts \cite{spp1}.

\textbf{9. Analytical reporting.} After the exam, administrators and teachers generate a QuestPDF report covering attendance, submission status, flagged incidents, and grade summaries. Every metric is linked to its source record, making the report fully auditable \cite{sommerville}.
