\section{Proposed Solution}

SmartExam joins scheduling, device-bound login, lockdown, live monitoring, submission and grading in one workflow. Its main benefits are:

\begin{enumerate}[noitemsep]
\item \textbf{Role-based access.} JWT login with rotating refresh tokens and five roles.
\item \textbf{Structured exams.} MCQ, coding and theory questions, test cases, allowed applications and a lockdown mode (Off, Report or Enforce).
\item \textbf{Device binding.} Each student account is bound to one workstation by a hardware ID built from BIOS, disk and motherboard serials.
\item \textbf{Locked exam window.} Fullscreen, topmost client that blocks Alt+Tab, the Windows key and Task Manager, guards the clipboard and reports or closes unapproved processes.
\item \textbf{Live proctoring.} A tile per student with timeline and screenshots; staff can warn, extend time or force a submission.
\item \textbf{Recorded incidents.} Every focus loss, blocked key, unapproved process or idle period is stored with its session and time.
\item \textbf{Safe submission.} 10-second autosave, AES-GCM encrypted local backup, offline queue, server-side deadline and a receipt hash.
\item \textbf{AI-assisted grading.} Docker test-case runs for code and TF-IDF scoring for theory, which the teacher can override \cite{eassess1}.
\item \textbf{Reports.} QuestPDF reports, analytics and an audit log per exam.
\end{enumerate}
