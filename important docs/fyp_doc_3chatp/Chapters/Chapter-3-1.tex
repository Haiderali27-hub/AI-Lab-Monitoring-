\chapter{SOFTWARE PROJECT PLAN}
\label{chap:spp}

This chapter describes how we plan, manage, and deliver the AI-Driven Lab Exam Monitoring and Management System across a two-semester FYP timeline \cite{spp1}. Building twelve integrated modules under academic deadlines is not simply a coding exercise. It requires explicit planning so that authentication, monitoring, submission, and reporting modules arrive in the right order, in a usable state, at the right time.

The platform's modules are not independent. Scheduling logic feeds the monitoring dashboard. The monitoring dashboard feeds the incident log. The incident log feeds the final report. This dependency chain means a delay in one module cascades forward. The project plan addresses this directly: it maps deliverables, defines the schedule structure, identifies critical path activities, and catalogues risks with mitigation actions before they materialise.

The chapter covers five areas: project deliverables, scheduling artifacts (Gantt chart, WBS, CPM), managerial process assumptions, and risk management \cite{agile1}.
