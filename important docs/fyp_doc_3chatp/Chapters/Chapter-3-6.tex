\section{Project Risk Management}

We identify risks early, rate them, and plan one response for each \cite{risk1}.

\subsection{Risk Identification}

We use four risk types: technical (R1--R7), schedule (R8), academic (R9) and resource (R10, R11).

\subsection{Risk Mitigation Plan}

Each response matches the risk with the same ID in Table~\ref{tab:risk_matrix}.

\begin{description}
    \item[R1:] The client hashes the BIOS, disk and baseboard serials into a hardware ID, and the first login binds the account to it. Logins from other devices are refused. VMs and RDP sessions fail the readiness check and are reported by \texttt{DeviceGuardService} during the exam.
    \item[R2:] A low-level keyboard hook blocks Alt+Tab and the Windows key, Task Manager is disabled, and the exam window stays fullscreen and topmost. Ctrl+Alt+Del cannot be blocked, so focus loss is logged. If antivirus interferes, the teacher sets lockdown to Report mode.
    \item[R3:] Answers are autosaved every 10 s to an AES-GCM encrypted local backup. Failed saves are queued and resent on reconnect, and the client recovers answers after a crash. The teacher can extend time.
    \item[R4:] Clients send small REST heartbeats and send screenshots only every 30--90 s or on a violation. SignalR is used only for dashboard updates and invigilator warnings. We check Neon usage weekly.
    \item[R5:] Code runs in a fixed gcc Docker image, theory scoring uses deterministic TF-IDF, and LLM grading is off by default. Teachers review and can override every mark.
    \item[R6:] Package versions are fixed in lock files and project files, and are updated only when the full test suite passes.
    \item[R7:] Passwords are stored as PBKDF2 hashes, traffic uses HTTPS, and every endpoint checks the JWT and role. No biometric data is stored.
    \item[R8:] Each module is merged with its xUnit and headless Playwright tests, so integration happens every sprint. Sprint 8 adds no new modules.
    \item[R9:] Updating the thesis section is part of each task's definition of done.
    \item[R10:] Work is split by area (client, backend, web) in a shared Git repository, so another member can take over a module.
    \item[R11:] Most tests run on our own PCs against an in-memory backend. Lab PCs are booked only for manual lockdown and webcam checks before each demo.
\end{description}
