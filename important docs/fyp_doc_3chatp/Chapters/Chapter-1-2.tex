\section{Product Scope}

SmartExam covers a lab exam from set-up to final report. We drew the scope boundary \cite{scope1} around the institution's own lab: exams on Windows PCs on campus, not at home. The WPF client on each workstation and the React web panel for staff both call an ASP.NET Core 9 API that stores data in Neon PostgreSQL. The client uses HTTPS REST. SignalR carries live updates to the web dashboard and pushes invigilator warnings to students. The work is split into twelve modules:

\begin{itemize}[noitemsep]
\item M1 Authentication and Device Binding
\item M2 Pre-Exam Verification and Practice Exam
\item M3 Student Exam Dashboard
\item M4 Secure Exam Environment (lockdown)
\item M5 Live Monitoring Client Service
\item M6 Submission and Backup
\item M7 User and Role Management
\item M8 Exam Creation and Configuration
\item M9 Eligibility and Access Control
\item M10 Live Proctoring Dashboard
\item M11 AI-Assisted Evaluation
\item M12 Logs, Analytics and Audit Trail
\end{itemize}

\subsection{Existing System Description}

The manual process is described in Section~\ref{sec:productpurpose}. Existing tools each solve one part of it. We reviewed ten of them; the five closest to our needs are summarised below, and Table~\ref{tab:comparison} compares all ten.

\subsubsection{Respondus LockDown Browser}
It stops students from opening other websites or applications, printing, or copying during an online quiz, and it works with Canvas and Blackboard. Webcam recording needs the separate Respondus Monitor product \cite{respondus1}. It is built for home testing. It cannot bind a student to a lab seat, and it cannot compile or grade code.

\subsubsection{Safe Exam Browser}
Safe Exam Browser (SEB) is an open-source browser that limits the PC to an online exam page. A configuration file decides which sites are allowed \cite{seb1}. It runs on Windows, macOS and iOS, but it has no compiler, no seat management and no live view for invigilators.

\subsubsection{MOSS}
MOSS (Measure Of Software Similarity) from Stanford compares source files from different students and ignores shared starter code \cite{moss1}. It is a plagiarism checker only. It does not lock machines, check who is sitting the exam or run code.

\subsubsection{Proctorio}
Proctorio combines webcam video, automated behaviour analysis and a browser lockdown, and it plugs into common LMS portals \cite{proctorio1}. It targets remote exams and cannot tie a student to a lab workstation or its network address.

\subsubsection{Moodle}
Moodle is an open-source LMS with quizzes, courses and a large plugin library \cite{moodle1}. Its core has no workstation lockdown, no live supervision console and no way to run submitted code.

\subsubsection{Other Platforms}
The other five tools share the same gap. ExamSoft runs exams offline in a locked desktop client but has no code execution or seat assignment \cite{examsoft1}. Honorlock checks student identity and supports live remote proctoring for online exams \cite{honorlock1}. Blackboard Learn \cite{blackboard1}, Canvas \cite{canvas1} and Google Classroom \cite{gclassroom1} manage courses, assignments and grades, but give no control over lab machines.

None of these tools combines desktop lockdown, workstation binding, live supervision, code execution against test cases and an audit trail for an exam held in a physical lab. SmartExam is built to fill that gap.

\subsection{Analysis of Future System Use}

The administrator registers labs, workstations and users. The teacher creates the exam, imports attendance and assigns eligible students to seats. On exam day each student logs in at the assigned PC, passes the readiness check and works in the locked client while invigilators watch the live dashboard. When the exam closes, the server grades the answers, builds the plagiarism matrix and generates PDF reports, and the teacher confirms or overrides the marks. Every login, violation, grade change and staff action stays in the audit log. The system suits programming, database and networking lab exams.
