\subsection{System Testing}\label{subsec:system_tests}

System tests check complete user flows in the Playwright \texttt{chromium} project: the web panel runs in headless Chromium, and the desktop-client simulator sends the HTTP calls of the WPF client in the same test, so one action can be followed from the student PC to the teacher's screen and back. Each test creates its own students and exam. Of the 113 tests, 111 passed, none failed, and M12-E-04 and M12-E-05 were skipped and are not listed. One system test case may combine several catalogue tests of the same flow; all the tests it cites passed.

Six (D-07, D-16, D-19, D-20, D-22, D-26) were found by code review, and one (D-33) was a flaky test rather than a product defect. Table~\ref{tab:bugs} lists the 20 with the largest effect on exam integrity, data access and reliability; every test named in it is kept as a regression test and passed in the final run. Most serious defects were access-control faults that appear only when two users of the same role meet, or failure paths of the desktop client (crash, network loss, camera error) found by unit tests with fakes. In summary, SmartExam was tested at three levels with 915 automated tests, of which 900 passed, none failed and 15 were skipped, and every test case marked Pass in this chapter is backed by a passing test from that run. The 47 defects recorded during testing are all fixed; those found by a test are kept as regression tests. The checks that need a real lab PC, the load test and the unfinished Module~12 features (audit hash chain and report exports) are still pending and are reported as such.
